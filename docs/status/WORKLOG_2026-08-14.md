## 六、Phase 2 设计修订（本会话，玩家三轮问答定案）

### 6.1 采收后植株状态

- **回退到阶段 2**（植株），可多次采摘；**采摘次数由基因型决定**（多基因共同控制，见 6.2）
- 次数耗尽 → **整株枯萎**（新增 `BlockType.PeaWithered`，矮茎 2 格 / 高茎 3 格全变枯萎），由玩家左键破坏去除（无掉落）；贴图先占位（复用豌豆底格 tile），待玩家跑 `main.py` 生成后替换

### 6.2 新基因位点 7「采收潜力」+ 多基因数量性状模型

- **硬约束**：`Genome` 打包 uint32，7 位点 × 4bit = 28bit，bit28-31 预留恰好容纳第 8 位点 → **数据结构零改动、存档完全兼容**（旧档该段 = 0 = 隐性）
- **寿命（采摘次数）**：指数模型，6 个位点共同控制（{0,1,3,5,6,7}，排除纯观赏的花色 2 与豆荚色 4）：
  `上限 = min(2^(1 + 纯合显性位点数), 64)`；分布 2/4/8/16/32/64，期望 ≈ 5.7 次（6-8 常见、64 稀有）
- **产量（单次豆荚数）**：累加模型，3 个位点共同控制（位点 3 豆荚形状 +2、位点 4 豆荚颜色 +2、位点 7 采收潜力 +4）：
  阶段 4 豌豆荚 = `12 + Σ(显性贡献)`（12~20）；阶段 3 青嫩豆荚 = `3 + Σ/2`（3~7）
- 生物学叙事：种子形状/子叶色/花位/茎高 = 植株活力（决定采摘轮数）；豆荚形状/豆荚色/采收潜力 = 结实能力（决定每轮产量）
- 次数存储：方块状态位 bit20-26（7 bit，0=未初始化，1-64=剩余）——块值随 `.vrf` 保存，**存档零改动**；`WithStage`/`WithTall` 只改各自掩码位，互不干扰

### 6.3 其他修订

- **中段/顶端也可采收**：命中 `PeaPlantMiddle`/`PeaPlantTop` 时向下找底部格（矮茎顶格 y-1；高茎中格 y-1、顶格 y-2）取基因与次数
- **显示名保持简单名**（「青嫩豆荚」/「豌豆荚」），表型标签仅作内部堆叠分组键
- 阶段 <3 采收 → OnGUI 瞬态提示「未成熟」（1.5s）
