### 5. Step 1f：存档 v2 —— tile（基因/世代/生长时间）持久化

> 状态：代码已完成并静态审查通过；**未进编辑器 Play Mode 验证**（用户暂停去配置模型 URL/API Key，改完需进编辑器编译）。

**设计定案**：外层扇区格式与文件头完全不动（仍 `VRF1` + version=1），载荷自描述，v1 旧档零迁移兼容：
- v1 载荷解压后恰好 16384B（纯块数据）；v2 载荷解压后 >16384B 且 magic `'V''2'` 开头 —— 长度判别无歧义
- v2 布局：`[0..1] magic` + `[2..5] tileCount(大端)` + `tileCount × 14B 记录（ushort key | uint genome | int generation | int growthTime(SingleToInt32Bits)）` + 尾随 16384B 块数据（native 端序，与 v1 一致）

**修改文件**
- `World/Saver.cs` — 新增 `TileSaveRecord`（纯值 struct）+ `SaveTask.Tiles`；`SaveVoxelChunk(VCPosInWorld, Block[,,], TileSaveRecord[])` 新重载（2 参旧重载委托传空数组）；`TryLoadVoxelChunk` 签名改为 `bool (vcPos, out Block[,,], out TileSaveRecord[])`；静态 `SnapshotTiles(Dictionary<ushort, PeaTileData>)`（**须主线程调用**，产出纯值数组交 worker 只读）；`ZlibChunkCompressor` 新增 `Compress(uint[,,], TileSaveRecord[])`（v2 容器）+ `ChunkPayload` + `DecompressPayload(byte[])`（v1/v2 判别 + 长度校验），v1 旧 API 保留不动
- `World/VoxelChunkData.cs` — 新增 `loadedTiles` 字段 + `SetLoadedTiles/GetLoadedTiles`（后台线程构造、主线程消费，纯值跨线程安全）
- `World/TerrainGenerator.cs` — 读路径改用新签名，命中存档时 `SetLoadedTiles(tiles)` 随数据传给主线程
- `World/ChunkStreamer.cs` — `CreateChunk` 成功后把读回的 tile 快照回挂到 chunk（`vc.SetTile(key, new PeaTileData(new Genome(value), generation) { GrowthTime = ... })`）
- `World/ChunkStore.cs` — `UnloadChunk` 保存前先 `Saver.SnapshotTiles(vc.TilesRaw)`（主线程快照）；`ForEachLoadedChunk` 新增 3 参重载（含 `Dictionary<ushort, PeaTileData>`，可能 null），旧 2 参保留
- `World/World.cs` — `SaveAllLoadedChunks` 改用 3 参重载并快照 tile

**线程纪律**：tile 快照/回挂全在主线程；worker 只读 `TileSaveRecord[]` 纯值数组与字节流；`DecompressPayload` 跑后台生成线程，不碰 Unity 对象。

**边界**：v1 旧档读回 → blocks 正常、tiles 空（豌豆保留 stage 外观但不继续生长，孤儿 tile 兜底本次不做）；0 tile 也写 v2（tileCount=0）→ 全档统一 v2。
