# 豌豆渲染方案（讨论稿，2026-08-10）

> 状态：**待玩家确认**。本文档记录豌豆视觉层的候选方案与推荐路线，供决策参考。
> 关联：`GAME_DESIGN.md` §6 豌豆性状设计、§7 待细化（"豌豆如何实体化"）。

## 1. 问题拆解

"如何渲染豌豆"分两层，建议分开决策：

- **数据层**（豌豆是什么）：类型 + 性状 + 生长阶段如何存储
- **视觉层**（豌豆长什么样）：7 对性状哪些可见、如何绘制

### 数据层（基本免费，已具备条件）

- 块值 = 类型（低 16 位）+ 状态（高 16 位，`StateMask 0x000F_0000`）
- 豌豆 = 1~2 个 `BlockType`（如 `PeaStem`、`PeaPod`）
- 状态位编码：生长阶段（2 位）+ 7 对性状各 1 位 + 预留
- 存档（.vrf uint）、确定性生成、交互系统**零改动兼容**
- P3-2 状态位修复（2026-08-10）正是为此铺路

## 2. 视觉层候选路线

| 路线 | 做法 | 优点 | 缺点 | 成本 |
|------|------|------|------|------|
| A. 方块贴图 | 1 格立方体贴豌豆图 | 零新系统 | 表现不了茎高/花位，方块感强 | 最低 |
| **B. 十字面片（推荐）** | 2 个交叉四边形面片 + 透明贴图，并入 chunk mesh | 植物感强；体素管线全兼容（生成/剔除/存档）；性能好（合并进 chunk mesh） | 需要透明渲染 + 图集 alpha | 中 |
| C. 独立模型 | 豌豆为独立 GameObject 低模 | 表现力最强、可动画 | 脱离体素管线（卸载/存档/确定性另做）；每棵一个 DrawCall | 最高 |
| D. 程序化几何 | 细柱茎 + 扁叶 + 小花块（现有图集） | 无外部资源、体素感统一 | MeshData 复杂度大增，性状靠几何参数拼 | 中高 |

## 3. 推荐路线：B，两步迭代

### 第一步（玩法验证优先）
- 十字面片 + 生长阶段视觉：绿苗 → 开花 → 结荚
- 7 对性状**先只存数据、不做视觉差异**
- 目标：跑通"种豌豆 → 杂交 → 收获 → 看性状"育种循环（GDD 核心玩法）

### 第二步（表现力）
- 图集加花色/豆荚色贴图，性状视觉差异逐个点亮
- 顺带验证方向语义修复（P3-3：侧壁/面片贴图终于有实际用途）

## 4. 性状 → 视觉映射（B 路线下）

| 性状 | 视觉方案 |
|------|----------|
| 高茎 / 矮茎 | 矮茎 1 格面片；高茎 2 格（上下两段块） |
| 紫花 / 白花 | 顶花面片贴图（图集加 2 张） |
| 花腋生 / 花顶生 | 顶生 = 顶端面片带花；腋生 = 中部面片带花 |
| 豆荚饱满 / 皱缩、绿荚 / 黄荚 | 结果期侧面片加豆荚贴图（图集加 4 张，或程序调色） |
| 圆粒 / 皱粒、黄子叶 / 绿子叶 | **数据层**（收获时面板显示），世界内不可见 |

## 7. 决策记录（2026-08-10）

**已定**：先 B（十字面片）验证玩法循环，后续升级 D（程序化几何）作为最终形态。

### 关键设计原则：数据先行

豌豆在世界里永远是"一个块值 + 一块 mesh 区域"。块值 = 类型（低 16 位）+ 状态（高 16 位），状态位编码：生长阶段 2 位 + 7 对性状各 1 位 + 预留。
渲染层只是把这段空间画成什么样子：B 画成交叉面片，D 画成茎/叶/花/豆荚立体几何。
**B→D 升级只改 MeshData 豌豆分支 + 贴图**，数据模型/存档/交互/生成全部不动。

### 实施路线

| 阶段 | 内容 | 涉及 | 验证标准 |
|------|------|------|----------|
| 0. 前提确认 | 渲染管线（Built-in/URP）、材质透明支持、图集 alpha | 材质/图集 | 确认 cutout 渲染可行 |
| 1. 数据模型 | `BlockType.PeaStem` + 状态位编码（生长阶段 2 位 + 7 性状各 1 位）；注册表、图集占位贴图 | `Block.cs`/`BlockRegistry.cs`/`BlockUVMap.cs` | 种下→保存→读回，性状/阶段不丢 |
| 2. B 视觉 MVP | MeshData 豌豆分支：交叉面片（X/Z 对角）+ 随生长阶段变高；Alpha Test 材质；种植/生长交互 | `MeshData.cs`/材质/交互 | 豌豆可见、随阶段变化、可破坏、存档正常 |
| 3. 育种循环 | 收获→种子（带性状）→再种；性状数据流打通（视觉先统一） | 交互 + 数据层 | 杂交→收获→子代性状正确 |
| 4. D 升级 | MeshData 豌豆分支换程序化几何：茎（细柱，高度随阶段/高矮性状）+ 叶（扁薄片）+ 花（顶部小块，色随紫/白）+ 豆荚（侧挂，色/饱满随性状） | 只动 MeshData + 贴图 | 立体豌豆、性状视觉差异全点亮 |
| 5. 细化（可选） | 随机变体、摆动、光照响应 | 视效果而定 | 观感达标 |

### 关键机制决策：生长时间推进（必须先定）

当前世界纯静态（无任何时变内容），豌豆是第一个"时变内容"。选项：

1. **全局 tick（推荐）**：`World.Update` 每 N 秒扫"含豌豆 chunk 列表"推进阶段。简单可靠，性能可控
2. **时间戳粗粒度**：状态位存种植时刻（8 位 ≈ 256 分钟），重进/加载时按真实时间补算。省运行时开销但精度有限
3. **交互驱动**：右键"照料"推进。最省但无"自然生长"体验

### 决策定案（2026-08-10，玩家确认）

1. **渲染管线**：Built-in（查实：manifest 无 URP 包、Graphics 无 SRP 引用、材质为内置 Standard + `_Mode:1` Cutout + queue 2450——透明裁剪渲染现成可用）
2. **豌豆贴图**：程序生成占位（色块/渐变区分生长阶段，玩法验证后美术替换）
3. **生长机制**：全局 tick（`World.Update` 每 N 秒扫含豌豆 chunk 列表推进阶段）
